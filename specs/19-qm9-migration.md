# 19 — Repair the QM9 migration (RuleGNN → SimpleGNN)

## Context

`experiments/base_paper/MIGRATION_PLAN.md` Phase 8 declared the QM9 experiment
unrecoverable: `experiments/base_paper/QM9.sh` was left as a placeholder that
prints a notice and exits 1, because `regression/QM9/main_QM.py` and its configs
"were lost in the repository migration".

They were not lost — they live in the pre-refactor repo at
`~/Documents/CodeProjectsGit/GNNs/RuleGNN/ReproduceExtended/`:

- `main_QM.py`
- `configs/QM/main_config_QM.yml`
- `configs/QM/network_qm9_multihead.yml`

Everything the experiment needs is still supported by the current framework:

| Requirement | Status in `src/simplegnn` |
|---|---|
| `source: QM9` | allowed (`configuration_checks.py:118`) |
| QM9 loading/preprocessing | `QMGraphDataPreprocessing` (`graph_dataset_preprocessing.py:242`) |
| `regression_targets` | consumed (`graph_dataset.py:952`) |
| `output_features: {normalization: standard}` | consumed (`graph_dataset.py:965`) |
| label types `induced_cycles`, `wl_labeled`, `wl_labeled_edges`, `primary` | all present (`ShareGNN/preprocessing/preprocessing.py`) |
| property `distances` | present |

The only genuinely missing piece is the **split file**. The old config used
`split_function: qm_splits` (RuleGNN `src/Preprocessing/split_functions.py:43`);
the current framework requires the split JSON to exist at `FrameworkMain`
construction (`configuration_checks.py:80-86`). The file the placeholder script
points at — `src/simplegnn/datasets/splits/tu_splits/QM9_splits.json` — is
**not** the right split: it is a 10-fold CV split with empty `test` lists
generated by `utils/tu_splits.py` for the *TU* QM9 dataset, not the 1-fold
80/10/10 split over PyG's QM9 that the experiment used.

**Scope decision (user):** the reconstructed experiment lives in its own
top-level `experiments/qm9/` directory, not under `experiments/base_paper/`.

## Work

### 1. Split generation — `src/simplegnn/utils/qm_splits.py`

Port RuleGNN's `qm_splits` exactly so the split is reproducible:

```python
indices = list(range(len(dataset)))
random.seed(42); random.shuffle(indices)      # stdlib random, not numpy
train = indices[:int(0.8 * n)]
validation = indices[int(0.8 * n):int(0.9 * n)]
test = indices[int(0.9 * n):]
```

Emit the framework's split JSON format (a list with one fold):
`[{"test": [...], "model_selection": [{"train": [...], "validation": [...]}]}]`
to `src/simplegnn/datasets/splits/fixed/QM9_splits.json` (same home as the ZINC
fixed splits). CLI entry point so it can be regenerated.

### 2. Configs — `experiments/qm9/`

Mirroring the `experiments/ogb/` layout plus a runner:

- `configs/main_config_QM9.yml` — three-tier main config: `source: QM9`,
  `task: graph_regression`, `regression_targets: [0]`, `validation_folds: 1`,
  `paths: {data, labels, properties, results, models, hyperparameters, splits}`.
- `parameters_QM9.yml` — everything that was inline in the old main config:
  Adam / MAE / batch 64 / lr 1e-3 / 400 epochs / ReduceLROnPlateau /
  `rule_occurrence_threshold: 1` / `weight_initialization` / `input_features` /
  `output_features` / `best_model`. Drop `bias` (no consumer).
- `models_QM9.yml` — the migrated `network_qm9_multihead.yml`.

Model config renames (verified against `layer_loader.py` / `framework_layer.py`):

| Old | New |
|---|---|
| `networks:` | `models:` |
| `layer_type: convolution` | `invariant_based_convolution` |
| `layer_type: aggregation` | `invariant_based_aggregation` |
| `output_features:` (linear) | `out_features:` |
| `mode: aggr_heads` | `mode: aggr_channels` |
| `activation: 'LeakyReLU'` | `'torch.nn.LeakyReLU()'` |
| `activation: 'None'` | `'torch.nn.Identity()'` |
| aggregation `out_dim: 10` | drop; `num: 10` on each head |
| conv heads without `num` | `num: 1` per head |

### 3. Two deliberate deviations from the old config

Both are cases where the old config declared something the code never applied.
Documented in-file so they can be reverted with a one-line edit.

1. `input_features` — old: `{name: node_labels, transformation:
   one_hot_labels_normalize_features}`. `one_hot_labels_normalize_features` is
   only reachable when `name == 'all'` (`graph_dataset.py:788,878`), in the old
   repo too (`GraphData.py:579,666`), so the old run silently fed a *single*
   raw atomic-number column. Migrate to `name: all`, which is what the
   transformation name asks for (one-hot atom type ⧺ min-max-normalized
   attributes + 3D positions). Revert by setting `name: node_labels`.
2. `invert_outputs` — old config had it commented out while
   `output_features: {normalization: standard}` was active, so the reported MAE
   was in z-scored units. Enable `invert_outputs: {normalization: standard}` so
   the metric is in target units (`model_configuration.py:1209-1213`).

- `experiments/qm9/main_QM9.py` — `FrameworkMain` five-step workflow, `click` CLI

- `experiments/qm9/run_qm9.sh` — modeled on `ZINC.sh`, with the venv check fixed

- Delete `experiments/base_paper/QM9.sh` (the broken placeholder) and update
